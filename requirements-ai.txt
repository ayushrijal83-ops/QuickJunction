# Quick Junction -- local AI stack (Milestone 07).
#
#   pip install -r requirements-ai.txt
#
# Needed for: local Qwen inference (app/services/local_llm.py) and LoRA
# fine-tuning (training/train_lora.py).
#
# The web application still runs without this file. If these packages are
# absent, app/services/local_llm.py logs a warning and returns None, and
# /recommendations/explain shows "AI explanation temporarily unavailable"
# while every deterministic feature keeps working.
#
# The Qwen3-0.6B-Base weights live in models/ and are git-ignored.
#
# ---------------------------------------------------------------------
# Corrected in M07. The previous version of this file did not describe the
# installed environment: it claimed torch==2.13.0 and transformers==5.15.0,
# and transformers/accelerate/safetensors were in fact not installed at all,
# so the "verified to load on CPU" claim could not be reproduced. Every pin
# below was verified against the actually installed, working environment --
# see docs/AI.md.
#
# (Correction to that correction: the M07 note claimed those two versions did
# not exist. They do -- both are published on PyPI. What was wrong was that
# they did not describe this project's environment, which is the part that
# mattered. The pins below are the ones V4 was trained and evaluated on.)
# ---------------------------------------------------------------------
#
# VERSION COMPATIBILITY -- READ BEFORE CHANGING ANY PIN BELOW
#
# These pins are mutually consistent and were re-verified end to end on
# 2026-08-20 in a clean virtual environment: `pip check` reports no broken
# requirements, the V4 LoRA adapter loads through app/services/local_llm.py,
# and the full suite passes 420/420.
#
# There is exactly one combination known to break, and this file does not
# produce it:
#
#     peft==0.17.1  +  transformers 5.x
#       -> ImportError: cannot import name 'HybridCache' from 'transformers'
#
# peft 0.17.1 imports HybridCache from transformers at peft/peft_model.py;
# that symbol was removed in transformers 5.0. The failure therefore only
# appears on a machine whose transformers has drifted ABOVE the 4.57.1
# pinned here -- installing this file as written never hits it.
#
# The symptom is quiet rather than loud: local_llm catches the ImportError,
# logs "Could not load LoRA adapter; continuing with base model", and serves
# the untuned base model. If you see that line, your environment has drifted
# from these pins. The fix is to restore them, not to bump peft.
# ---------------------------------------------------------------------

# CPU build. No GPU is required or assumed anywhere in this project.
torch==2.10.0

# >=4.51 is REQUIRED: that is the release that added the `qwen3`
# architecture, which models/Qwen3-0.6B-Base/config.json declares.
transformers==4.57.1

# LoRA / parameter-efficient fine-tuning, and its Trainer backend.
peft==0.17.1
accelerate==1.14.0

# Weight loading. safetensors only -- never pickle (docs/SECURITY.md).
safetensors==0.8.0
tokenizers==0.22.2
huggingface_hub==0.36.2

# NOTE ON NUMPY -- resolved conflict.
# This file previously pinned numpy==2.2.6 while requirements.txt pinned
# 1.24.3, so installing both together was impossible. Both now agree on
# 1.24.3: it is the version already installed and verified working with
# scikit-learn 1.7.2 / scipy 1.15.3 (the recommendation engine) *and* with
# torch 2.10 / transformers 4.57.1 (this stack). Standardising on the
# verified-working version rather than upgrading either side avoids
# revalidating the binary compatibility of four compiled packages under
# deadline. numpy is pinned in requirements.txt; it is intentionally not
# re-pinned here so the two files cannot drift apart again.
